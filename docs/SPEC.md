# SPEC — ExpDeck

状态：待实现
日期：2026-11-11
术语：全部按 `CONTEXT.md`；意图见 `INTENT.md`；架构见 `DESIGN.md`

---

## Problem Statement

研究者的实验跑在服务器上，代码在 git 里，但**"为什么做、结果多少、为什么停"这三件事没有任何地方留存**。

现状是：agent 在 worktree 里跑完实验，把输出和权重复制到一个集中目录；记录结构每次靠临场发挥；权重太大不能进 git；实验一多，worktree 目录乱到不敢建新的；**三个月后再看，只记得"当时好像试过"，不记得结论**。

已有的实验平台解决的是"结果在哪看"，不解决"这次改动为什么存在"。而手写笔记的系统一定会死——靠自觉的东西都活不过两周。

## Solution

ExpDeck 是一个 Go 单二进制。

- **agent 用命令**：建实验、跑、写结论、卸载，全程不碰 git。
- **人用浏览器**：看树、看 diff、读笔记、改笔记、必要时点运行。
- **记录的真相是普通文件**：放在仓库的 `.git/exp/records/`，随时能 `grep`、能 `cat`、能手改；`book` 分支只是它的备份历史。
- **每个 run 自动打一个代码快照**，并用 ref 保住，所以"从指标回到当时的代码"几年后仍然成立。
- **权重进内容寻址的对象库**，`run.json` 里只留 sha256 指针。

一句话：让"三个月后还记得"成为默认结果，而不是靠自觉。

## User Stories

### 接入项目

1. 作为研究者，我想要在已有 git 仓库里运行 `exp init` 就把项目接进来，以便不用先读一大段文档。
2. 作为研究者，我想要 `exp init` 在没有 git 仓库时拒绝执行并说明原因，以便工具不会替我做不可逆的决定。
3. 作为研究者，我想要 `exp init` 读一遍仓库后生成 `exp.toml` 草稿（启动命令、指标位置、产物位置），以便我只改几行而不是从零写。
4. 作为 agent，我想要 `exp init --json` 告诉我还有哪些字段需要确认，以便我能自己补全配置。
5. 作为 agent，我想要 `exp init` 往仓库写一段 agent 说明，以便下一个会话知道这条命令该怎么用。

### 实验

6. 作为研究者，我想要 `exp new sensitive/hyperparameter --why "..."` 创建实验，以便假设在开始那一刻就落下来。
7. 作为 agent，我想要不写 `--why` 就创建失败，以便"为什么做这个实验"永远不会是空的。
8. 作为研究者，我想要实验路径按 `/` 分层，以便扫参的不同取值能归在一个文件夹下。
9. 作为研究者，我想要 `exp ls` 打出一棵树并标注状态，以便一眼看完整个项目。
10. 作为研究者，我想要 `exp show <exp>` 看到假设、笔记、所有 run 和指标，以便不用翻目录。
11. 作为研究者，我想要 `exp show <exp> --diff` 看到相对实验起点的全部改动，以便知道这条线一共改了什么。
12. 作为研究者，我想要 `exp show <run>` 看到那个 run 自己的改动（上一个快照到本快照），以便知道"上次挂了之后我修了什么"。

### 笔记

13. 作为研究者，我想要 `exp note <exp>` 打开 $EDITOR 改整篇，以便在终端里写长文本。
14. 作为 agent，我想要 `exp note <exp> --append "..."` 追加一段带时间戳的观察，以便不用重写整篇。
15. 作为研究者，我想要网页里点「编辑」直接改，以便看到问题时立刻补一句。
16. 作为研究者，我想要保存时如果笔记被别人改过就拒绝并提示，以便不会静默覆盖 agent 刚写的内容。
17. 作为研究者，我想要笔记永远是纯文本 markdown，以便十年后还能用任何编辑器打开。

### 挂载

18. 作为研究者，我想要 `exp attach <exp>` 把分支检出到独立目录，以便并行跑多个实验。
19. 作为研究者，我想要 attach 前做一次预检（数据软链、环境文件、依赖声明），以便不会跑到一半才发现环境缺东西。
20. 作为研究者，我想要 `exp detach <exp>` 先把未提交改动固化成 patch 再删目录，以便卸载实验不会丢代码。
21. 作为研究者，我想要 detach 之后记录、笔记、历史 run 一条不少，以便"收进抽屉"不等于删除。
22. 作为研究者，我想要 `exp attach --restore-dirty` 能恢复上次没提交的改动，以便换机器接着做。

### 运行

23. 作为 agent，我想要 `exp run --exp <id>` 立刻返回一个 run 标识，以便我的会话不会被几个小时的训练卡住。
24. 作为研究者，我想要运行的命令来自 `exp.toml` 且能被覆盖，以便不同项目用不同启动方式。
25. 作为研究者，我想要同一实验同时只能有一个 run，以便串行语义不靠自觉。
26. 作为研究者，我想要两个 run 同时认领同一张 GPU 时报错，以便多个 agent 不会同时挑 3 号卡。
27. 作为研究者，我想要 `exp run` 前看到"这张卡已经被别人占着"的提示，以便不用等 OOM 才发现。
28. 作为研究者，我想要 run 的日志能实时滚动，以便判断还在训练还是卡住了。
29. 作为 agent，我想要 `exp wait --run <id>` 阻塞到结束并返回状态，以便我能等结果再决定下一步。

### 状态

30. 作为研究者，我想要杀掉监督进程后系统仍然认为实验在跑，以便不会重复开跑。
31. 作为研究者，我想要机器重启后所有"在跑"被收敛成"崩了"，以便状态不会永远骗人。
32. 作为研究者，我想要命令行、网页、等待命令对同一个 run 给出同一个答案，以便不用猜哪个是真的。
33. 作为研究者，我想要"进程活着但日志不动"显示成可疑，而不是自动改状态，以便我不被自动猜测误导。

### 快照

34. 作为研究者，我想要每个 run 开始前自动打一个代码快照，以便"这次改了什么"精确到 run。
35. 作为研究者，我想要快照在 git 常规清理之后仍然存在，以便半年后还能看到当时的代码。
36. 作为研究者，我想要快照包含未提交和未跟踪的文件，以便"脏工作区跑的那次"也能复现。
37. 作为研究者，我想要快照的 diff 不依赖工作区是否存在，以便 worktree 删掉之后还能看。

### 产物

38. 作为研究者，我想要权重按内容哈希存进对象库，以便同一份权重只占一份空间。
39. 作为研究者，我想要产物只登记本次新增或修改过的文件，以便不会把上一次的高分记到这一次头上。
40. 作为研究者，我想要脚本能直接写到一个专属输出目录，以便比靠通配符猜更可靠。
41. 作为研究者，我想要默认只保留最好的权重，以便磁盘不会被中间产物塞满。
42. 作为研究者，我想要 `exp gc` 按引用计数删掉没人再用的权重，以便记录还在、权重可丢。
43. 作为研究者，我想要权重可以配置到别的磁盘，以便 `.git` 所在的小盘不被撑爆。

### 结案

44. 作为研究者，我想要 `exp conclude <exp> --decision abandon --why "..."`，以便失败的知识也被留下。
45. 作为研究者，我想要放弃必须写原因，以便几个月后不会重走同一条死路。
46. 作为研究者，我想要 `exp reopen <exp>`，以便后来又想起它的时候能接上。

### 备份与恢复

47. 作为研究者，我想要 `exp backup` 把记录和快照一起推送，以便换机器能拿回来。
48. 作为研究者，我想要在新克隆里 `exp restore` 恢复全部记录和快照，以便 clone 就是完整交接。
49. 作为研究者，我想要网页上看到"有 N 条记录未备份"，以便不会忘了推。
50. 作为研究者，我想要 `exp backup` 是显式的，以便它不会在每次写笔记时制造一堆提交噪音。

### 网页

51. 作为研究者，我想要左侧是一棵树并带状态点，以便一眼看出谁在跑、谁刚跑完。
52. 作为研究者，我想要运行中转圈、完成未查看绿点、出错红点，以便不用点进去确认。
53. 作为研究者，我想要网页能点「运行」，运行中按钮变「中断」，以便没有 agent 的晚上也能开实验。
54. 作为研究者，我想要右栏标签由 `exp.toml` 的 `[cmds]` 生成，以便项目自己决定有哪些图表和评估。
55. 作为研究者，我想要图表标明数据来自哪个 run，以便不会被过期结果误导。
56. 作为研究者，我想要网页只监听本机并用端口转发访问，以便实验室共用服务器上不暴露端口。
57. 作为研究者，我想要网页上永远没有代码编辑区，以便它不会长成一个半成品 IDE。

### agent 契约

58. 作为 agent，我想要每个命令都支持 `--json` 并输出统一信封（含下一步建议），以便我不靠猜文本格式。
59. 作为 agent，我想要退出码区分用法错误、不存在、校验失败、冲突，以便决定重试还是放弃。
60. 作为 agent，我想要所有写操作支持 `--dry-run`，以便先看再动。
61. 作为 agent，我想要任何命令都不读标准输入、不弹交互提示，以便我不会被挂住。
62. 作为 agent，我想要 stdout 只放数据、stderr 放诊断，以便我能干净地解析。

### 维护

63. 作为研究者，我想要 `exp doctor` 报告孤儿实验、未登记分支、失效快照引用，以便漂移被发现而不是自动掩盖。
64. 作为研究者，我想要删掉 worktree 之后旧 run 的代码仍能找回，以便清理目录不是不可逆的。
65. 作为研究者，我想要删掉一个实验时它的 run 一起走，以便不会留下一堆孤儿目录。

## Implementation Decisions

### 形态

- 一个 Go 二进制，`exp` 为 CLI 入口，`exp serve` 提供网页；网页资源编译进二进制，无前端构建链。
- 无数据库、无常驻守护进程、无独立内核进程。两个前端共享同一个内部核心包。
- 每次命令都是一次短命进程：加载 → 操作 → 退出。

### 存储

- 数据根：`.git/exp/`，含 `records/`（记录）、`objects/`（产物）、`registry/`（存活登记）、`gpus/`（占位）、`logs/`（训练日志）、`cache/`、`boot`（开机标识）。
- `.exp/` 是每个检出各自的缓存（渲染产物、终端历史），可删。
- `exp.toml` 是唯一被提交的文件。
- **记录是普通文件，是唯一真相**；`book` 是 orphan 分支，保存记录树的历史快照，只由 `exp backup` / `exp restore` 读写。
- 记录布局：`exps/<exp_id>/meta.json`、`exps/<exp_id>/note.md`、`exps/<exp_id>/runs/<run_id>/run.json`、`.../scripts/`。`exp_id` 为 ULID，`exps/` 平铺，展示层级由 `meta.json.path` 推导。

### 契约与数据

- `exp.toml` 段：项目名、树前缀、产物库路径、运行命令与超时、运行环境变量、指标位置与主指标方向、产物通配与保留策略、命令清单（名称/命令/类型/作用域）、钩子（run 开始前、结束时）。
- `run.json` 字段：schema 版本、run 标识、所属实验、状态、结论（有效/无效/未评）、快照提交与基线提交、实际命令、工作目录、环境、起止时间、退出码、进程号与进程组、开机标识、指标、产物清单（名称/哈希/大小/库内路径）、日志路径。
- `meta.json` 字段：标识、路径、分支、假设、状态。**head / best 不存储**，每次从 run 记录推导。
- 工具不理解参数：命令模板只做字符串替换，实际执行的完整命令写入记录。

### 状态机

- run：`running | finished | interrupted | crashed`，另有 `outcome: valid | invalid | 空`。
- 实验：`active | concluded | abandoned`。
- **结局只写 `run.json`**；登记表只表示"现在谁活着"，可从记录与进程存在性重建。
- 存活判定用进程号 + 进程启动时间（防复用）；开机标识变化即视为全部死亡。
- 监督进程是记录员不是真相：它被杀而训练仍在跑时，实验仍视为占用，拒绝第二次启动。

### 快照

- run 开始前用临时索引把工作区全量（含未跟踪）写成树，生成提交，父提交为上一个快照。
- 该提交必须被 `refs/exp/snap/<exp_id>` 指向，否则会被常规清理回收；快照链式，每个实验一个 ref 指向链尾即可。
- 这些 ref 不随默认推送/克隆传输，备份与恢复必须显式带上。

### 笔记

- 唯一写入口：命令行替换、追加、编辑器保存、网页保存全部经过同一个函数。
- 该函数在同一把文件锁内完成：读取当前内容 → 计算哈希 → 与调用方期望哈希比对 → 写临时文件并原子替换。
- 版本不一致返回冲突，不覆盖。

### 产物

- run 开始前记录通配匹配到的文件清单（路径、修改时间、大小）；结束时只接受新增或修改过的文件。
- 产物以内容哈希入库，同盘用硬链零拷贝；保留策略默认只留最好的一份。
- 清理按引用计数，删除前确认没有 run 引用。

### 并发

- 同一实验同时只允许一个 run（实验级锁）。
- GPU 认领写占位文件，冲突即拒绝；另读显卡状态提示外部占用。
- 记录写入单写者 + 文件锁。

### CLI 契约

- 所有命令支持 `--json`；标准输出不是终端时自动切换为 JSON。
- 统一信封：成功/数据/错误（含错误码）/下一步建议。
- 退出码：0 成功、1 通用错误、2 用法错误、3 不存在、4 校验失败、5 冲突。
- 所有写操作支持 `--dry-run`。
- 不读标准输入、不弹交互；需要确认的操作走显式确认参数。

### 网页

- 只做三件事：渲染（树、详情、diff、日志流）、编辑笔记、启动/中断 run。
- 右栏标签由 `[cmds]` 声明生成；命令类型为画图/表格时只写渲染缓存，评估类不允许从网页触发。
- 只监听本机加令牌；无多用户。
- 没有代码编辑区、没有参数表单、没有实时预览。

### 规模

- 单项目十几个到几十个实验，每个实验几次到几十次 run。
- 全量扫描即可；不建索引。是否加索引以实测延迟为准，且必须是可删可重建的派生物。

## Testing Decisions

**什么算好测试**：只测外部行为——命令的 JSON 输出、文件树的最终状态、git 的实际状态、进程的真实退出。不测内部函数、不 mock git、不断言实现细节（比如"调用了哪个函数"）。

**测试缝**（从高到低，优先用最高的一条）：

1. **核心包的公开接口**：命令行与网页都经过它。绝大多数行为测试落在这里。
2. **命令行端到端**：临时目录 + 真实 git 仓库，跑完整命令序列，断言 JSON 与文件状态。协议类行为（信封、退出码、dry-run、不读标准输入）只能在这里测。
3. **网页**：只测路由返回与模板渲染的可见文字，不测样式与 JavaScript。

理想情况是主要靠第 1 条，第 2 条覆盖每个命令至少一次，第 3 条只覆盖"页面能打开、关键信息在"。

**先写验收测试再写实现**（红-绿-重构）。每个 run 级别的行为都对应一个可在临时仓库里复现的场景。

**必须覆盖的场景**（这些是设计里最容易在实现中丢掉的）：

- 脏工作区跑一次 → 备份 → 新克隆恢复 → 仍能展示当时的代码与 diff
- 杀掉监督进程、训练仍在跑 → 拒绝第二次启动 → 三个入口状态一致
- 两个写入者同时保存笔记，只有一个成功，另一个收到冲突
- 复用 worktree 跑第二次并提前失败 → 不会把上一次的指标记到这一次
- 删除实验 → 它的 run 一起消失，无孤儿
- 快照 ref 存在时常规清理不回收对象

**既有先例**：上一版原型用过"临时目录 + 真实 git 仓库"的测试方式（已随原型删除），新实现沿用这个思路。

## Out of Scope

- 指标聚合服务、多机调度、多人协作、云端同步
- 数据集版本管理（DVC 那一层）
- 权重跨机器同步、git LFS、外部对象存储
- 浏览器里的代码编辑、语言服务、跳转查找
- 语义检索 / 向量召回（改为列举全部实验）
- 交互式图表探索、可拖拉的 dashboard
- MCP / agent skill 封装（后续的薄壳）
- 从旧的集中记录目录导入历史数据（后续可做一次性迁移命令）
- Windows 下的完整验证（开发在 Windows，运行目标是 Linux）

## Further Notes

**分期**（每一期都能独立验收，不一次做完）：

| 期 | 内容 | 验收 |
|---|---|---|
| 一 | 接入、实验、笔记、挂载、卸载、网页只读与笔记编辑 | 记录在 `.git/exp`；删 worktree 后记录还在；并发改笔记不互相覆盖 |
| 二 | 运行、监督进程、状态判定、快照 + ref | 杀掉监督进程后拒绝重复开跑；三处状态一致；快照在清理后仍可读 |
| 三 | 产物、对象库、备份、恢复、清理 | 脏工作区 → 备份 → 新克隆 → 展示当时的代码；权重去重与回收正确 |
